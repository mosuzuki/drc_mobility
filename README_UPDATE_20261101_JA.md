# 2026年11月1日 差分更新（N169）

添付の `drc_mobility-main (8).zip` を基準とした変更ファイルだけのパッチです。元の全ファイルを再アップロードする必要はありません。削除が必要なファイルはありません。

## GitHubへの適用

1. 差分ZIPを解凍してください。ZIP自体をGitHubへアップロードしないでください。
2. `mosuzuki/drc_mobility` の `main` ブランチ、リポジトリのトップで **Add file → Upload files** を開きます。
3. 解凍した中身（`index.html`、`assets`、`data`、`scripts`、`raw`、`extracted`、`.github`、この説明書）を、ディレクトリ構成を保ってアップロードし、**Commit changes** を実行します。解凍時にできた外側のフォルダーをそのままアップロードしないでください。
4. `.github/workflows/pages.yml` と `.github/workflows/update-sitrep.yml` も上書きしてください。macOSのFinderで `.github` が見えない場合は Command + Shift + . で表示できます。必要ならGitHub上で各ファイルを開いて編集・置換してください。
5. **Actions** でPagesデプロイの成功を確認します。その後 **Auto-update latest INSP SitRep → Run workflow** で手動実行を1回確認してください。以後は6時間ごとの設定です。ワークフローが無効化されている場合は有効にしてください。
6. 公開ページを再読み込みし、DRCが **N169 / 2026年10月30日 / 10,414例 / 死亡5,372例** になったことを確認してください。

GitHub Pagesの設定は **Settings → Pages → Source: GitHub Actions** を想定しています。実際のリポジトリへのコミット・公開操作はこの納品には含めていません。

## 改修と再計算

- PDF表の改ページ、折り返された保健区名、総計欄の後ろに追加された割合列に対応。全国・州・保健区の累積値と日別値を照合します。
- 7/14/21/28日予測（LightGBM・Branching・アンサンブル）、260日規模の4シナリオ、報告補正後感染規模、Rt、CFRをN169基準で再計算しました。Chronos-2は従来どおり任意依存が未導入で、予測を生成したようには表示していません。
- 直近7日マップと保健区の最終新規報告日も、取得済みの24時間報告数を優先します。古い期間は従来の累積差分による近似が残ります。
- ウガンダの累積20例を毎日加算して「直近7日140例」としていた表示を修正しました。直近期間の日別報告がない場合は「—」を表示します。
- 自動更新は統合処理を実行し、データ取得後に推定・予測・検証まで実行します。機械学習の依存ライブラリーに加えて、表抽出に必要なPopplerを導入します。
- 更新botのコミット後にもPagesがデプロイされるようにしました。古い未取得報告の再試行、PDF本文優先、WHO国別表の追加取得、取得失敗の警告・レビュー通知も追加しています。
- 自動更新テストに古い国別人数が固定されていた部分を修正し、正当な人数更新でテストが失敗しないようにしました。

## 検証

- 添付10報の全PDFで全国・州・保健区の数値、報告日・公表日を検証。
- 予測整合性・時系列分割の検証、4期間・4シナリオ描画テスト、国別解析、遡及修正、ウガンダ日別値の回帰テストを通過。
- Chromiumで起動、最新KPI、8つのグラフ、予測期間・シナリオ切替を確認。JavaScript実行エラーなし。直近7日集計は535例・死亡255例で全国報告と一致。
- 検証環境では外部CDNを取得した実ファイルで補い、地図背景タイルの外部通信は確認できていません。地図の症例レイヤーは生成を確認しました。公開GitHub Actionsの実行は、アップロード後の確認が必要です。
- N169の「アラート調査率」は従来指標と新しい表の定義が一致することを保証できないため欠測を維持しています。ゼロや推測値を入れていません。
